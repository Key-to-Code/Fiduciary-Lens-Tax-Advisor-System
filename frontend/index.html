Measured on the current indexed corpus

Tax-law retrieval benchmark

01

This benchmark checks whether the hybrid search returns relevant statutory provisions near the top of its results. It evaluates the retriever and its grounding threshold together; it does not call the answer-generation LLM.

How to read these measures

Recall@K

How many test questions had at least one accepted provision within the first K retrieved passages. Here, 20 of 20 target provisions appeared in the top six.

Mean reciprocal rank

Rewards finding an accepted provision early: each question contributes 1 ÷ its first correct rank, or zero when none appears. The mean here is 0.917.

Off-topic refusal

The proportion of five unrelated control prompts rejected by the embedding cosine grounding threshold. This small control set is not a comprehensive safety or domain-classification test.

Benchmark scope. The in-scope set contains 20 hand-authored questions with accepted section/rule references; the control set contains five unrelated prompts. These results are useful for regression checks, but the sample is too small to establish general performance. Scores represent dense + BM25 retrieval, not either component in isolation.

Models and pipeline methods

02

The cards identify each model or algorithm used in retrieval, answer generation, and document analysis. A measured score is shown only where the repository has a reproducible evaluation. “Not benchmarked” means no valid performance score is available; it does not mean zero performance.

Current model coverage. The embedding model is the only deep-learning component with published measurements here, and those measurements cover the hybrid retrieval pipeline. The configured LLM is reported by the backend at runtime, but no live answer-quality evaluation has been run against it. The document pipeline reuses that LLM for summarization and some entity extraction.

Scoring logic checks · no live model calls

LLM evaluation harness

03

Five automated tests exercise the answer-scoring functions with fixed examples and a mocked provider response. The tests confirm that the checks behave as coded; they are not five successful live LLM answers and do not benchmark the configured OpenRouter model.

Faithfulness heuristic

Measures token overlap between answer sentences and retrieved excerpts. The harness expects at least 0.70; this lexical heuristic is not a semantic fact-checker.

Answer relevance heuristic

Measures overlap between non-stopword question terms and answer terms. The harness expects at least 0.50; it does not judge correctness.

Citations and safety checks

Checks expected citation text in the answer or source labels, plus simple refusal/disclaimer markers. These are rule checks, not legal validation.

    Interpretation. A passing harness indicates that the evaluator accepts or rejects its fixed examples as expected. It cannot be used as an accuracy, hallucination, or latency score for a deployed model.

    Source-level explainability

    Why these provisions were retrieved

    04

    Expand “Why this source ranked” on a cited source in chat or document insights to inspect its score breakdown. The breakdown comes from the actual search candidate pool for that request.

    This is a transparent decomposition of the existing retrieval score, not SHAP or LIME and not an explanation of the language model’s internal reasoning. The full method, equations, and limitations are documented in Model Evaluation and XAI.
